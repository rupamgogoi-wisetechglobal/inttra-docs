# Documentation style guide

- Write for the intended reader; define specialized terms on first use or link to the [glossary](../01-reference/glossary.md).
- Prefer direct, concise sentences and active voice. Use present tense for current behavior and explicit future tense for planned behavior.
- Use **must** for requirements, **should** for recommendations, and **may** for permitted options. Avoid ambiguous terms such as "normally" unless defined.
- Use headings in a logical hierarchy, descriptive link text, and tables for compact structured data.
- Write dates as `YYYY-MM-DD`; include time zone when a time is operationally significant.
- Keep acronyms consistent with the glossary. Preserve standard-defined names and segment/element identifiers exactly.
- Make examples realistic but synthetic, and label illustrative examples.
- Use relative links for repository files and check that links resolve before requesting review.
